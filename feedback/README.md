# feedback/ — 主动学习闭环

数据飞轮的"飞轮轴承"。把推理 / 仿真发现的问题转成下一轮采集 / 标注 / 训练任务。

## 子目录

| 目录 | 工业级职责 |
| --- | --- |
| `failure_mining/` | 失败挖掘：低置信、OOD、模型间不一致、人工接管、感知-规划不一致 |
| `replay/` | 闭环回放：把历史 session 在新模型上重放，标注新增失败 |
| `triggers/` | 重采集触发：把失败转为可下发到 `edge/` 的采集任务（场景 / 区域 / 时段） |
| `prioritization/` | 优先级 / 数据价值：信息增益、不确定度、稀有度、业务影响 |
| `rules/` | 规则引擎：什么样的失败 → 什么样的处理（标注 / 重采集 / 紧急修复） |

## 工业级实践要点

1. **失败定义要明确**：每类失败都有可计算的检测器，不能靠"看着不对"。
2. **闭环的成本要可控**：不是每个失败都重采集；先看能不能用已有数据重训。
3. **价值评估**：用信息增益 / Coreset 距离给候选样本打分，避免重复采集相似数据。
4. **任务下发安全**：触发的采集任务要带车队范围、地理范围、时段、停止条件，避免无限触发。
5. **闭环必须有指标**：飞轮的 KPI 是"失败 → 修复 → 不再发生"的周期时间和复现率。
6. **隔离实验回路**：实验性反馈策略放 sandbox，不要直接改主回路。

## 与其它层的契约

* 输入：`inference/monitoring` + `training/evaluation` + `processing/mining`。
* 输出：标注任务 → `labeling/`；采集任务 → `edge/ota/`；加权样本 → `training/datasets/`。
